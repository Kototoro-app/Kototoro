# iOS 收藏批量换源与来源恢复

## 用户流程

- 作品库右上角「批量换源」：选择当前分类、内容空间、搜索筛选下的收藏；也可切换「按原来源」，
  一次选择该来源在全部收藏和历史中关联的作品。来源分组按作品身份去重。
- 浏览页来源的长按菜单，以及扩展管理中来源行的长按菜单，提供「迁移此来源的收藏与历史」。
- 选择已启用的新来源后主动搜索。目标列表支持来源名称搜索与显式全选，空选表示不搜索。
- 候选复用共享标题／别名相似度排序。可逐部选择，也可主动点击「采用唯一同名候选」；
  多个同名候选保持待选择。名称相同不保证作者或版本相同，页面提示用户核对。
- 「保留原作品」默认开启，复制收藏分类和进度。关闭后，成功项移除原收藏和历史。
  执行前统一确认，只处理已选目标；章节在写入前读取，无章节、类型错误和身份冲突均拒绝写入。
- 逐项显示成功或失败原因，可停止后续任务、继续／重试。成功项保留，不再次迁移；
  多个原作品不能指向同一目标，也不能把本批原作品作为目标，避免隐式合并和迁移链。
- 作品库和历史显示缺失来源提示，扩展管理提供「补齐缺失来源」入口。恢复页展示来源数、去重作品数、
  收藏数和历史数，匹配扩展及仓库、逐扩展安装结果，并支持一键安装所选扩展。
- 没有匹配扩展时保留来源和作品，提供添加原仓库／站点配置与迁移该来源作品的入口。

## 批量操作体验优化

- 收藏与来源选择的「全选当前结果」只改变当前可见范围，保留其他搜索下的选择；
  空搜索结果禁用全选。收藏页同时展示已选总数和当前结果数，避免隐藏作品被意外选入。
- 「跳过」独立保存为批次状态，不再被批量搜索和唯一同名填充重新纳入。
  用户可以重新加入待处理，或主动选择某个候选恢复该作品。
- 迁移页底部常驻成功、待执行、待选择、跳过数量与当前进度；执行和停止按钮随滚动保持可见。
  成功行改为正常对比度的只读结果，全部成功后显示明确的完成状态。
- 缺失来源页支持名称／来源 ID／扩展检索，以及全部、可安装、需处理状态筛选。
  常见状态用简洁文案显示，技术身份和诊断说明放入「来源详情」。
- 扩展选择使用整行勾选；底部显示去重后的覆盖来源数与作品数，并明确安装包含其他筛选下的选择。
  可重新应用推荐组合，全选／取消选择当前扩展结果不会清空隐藏选择。

## 实现与复用

- `core-domain/SourceRecoveryRules`：按完整来源键统计收藏／历史引用，排除本地作品；
  根据精确覆盖关系选择扩展组合，尽量避免为同一来源推荐多个替代包，平局按包身份稳定排序。
- `ios-shared/IosLibraryRecovery`：通过现有库快照和 `source_origins` 提供统计与展示名称。
  来源可用时记住名称和提供扩展；备份中的既有仓库和定位信息继续保留，没有新增数据库 schema。
  仅元数据变化时写入，不因反复枚举来源重复更新全部记录。
- `IosExtension.sourceKeys`：仓库中的数字来源 ID 全程作为字符串桥接 Swift，保留生态前缀。
  Mihon、Aniyomi、Tsundoku 即使数字相同也分别匹配。解析器插件可以通过已记录的提供扩展身份匹配。
  缺少 ID 和提供扩展的旧数据保持未匹配，不按显示名称猜测安装包。
- `IosMigrationMatching`：复用 Android 已提取到 `core-domain/TitleMatchingRules` 的标题／别名规则。
  Swift 不重写匹配算法，也不把高相似度直接视为可自动替换的授权。
- `BatchMigrationModel`：负责搜索、人工选择、重复目标保护和批次状态；每部作品调用现有
  `IosLibrary.changeSource` → `SourceLibrary.migrate`，复用共享章节映射和事务。
  已有目标会合并收藏分类并保留较新的目标进度；原离线文件与书签继续归原作品。
- `RepositoriesModel.installBatch`：扩展更新与缺失源批量安装共用下载、转换、校验、安装、保持唤醒、
  串行调度、停止和逐项结果。安装后重新枚举来源；恢复情况以来源是否实际出现为准。
- `MissingSourcesNotice`：三个位置复用同一恢复页，依据库记录变化和来源枚举变化重新检查。

## 执行边界

搜索与迁移在前台执行。进入后台会停止后续项；当前网络／JNI 请求受现有超时约束，不能承诺立即中断。
迁移在请求返回、写入前检查停止状态；已开始的单作品事务会完整结束。
安装中的当前扩展结束后停止后续安装。应用进程结束后，已完成的数据和来源元数据保留；
未执行的候选计划不持久化，重新打开需重新选择。页面不会承诺后台持续执行。

当前仅在用户已添加的仓库中推荐；不会静默添加仓库、猜测扩展或批量安装未匹配内容。
原 CMS／TVBox 来源通过原配置恢复，不属于 APK／JAR 扩展安装。

## 验证入口

```sh
./gradlew :core-domain:jvmTest :ios-shared:iosSimulatorArm64Test \
    -PiosSimulatorDevice=<UUID>

python3 "iosApp/Scripts/serve-cms-fixture.py"
xcodebuild -project "iosApp/Kototoro.xcodeproj" -scheme "Kototoro" \
    -configuration Debug -destination 'platform=iOS Simulator,id=<UUID>' \
    -derivedDataPath "iosApp/build/RecoveryDefault" CODE_SIGNING_ALLOWED=NO \
    -parallel-testing-enabled NO \
    -only-testing:KototoroUITests/BatchSelectionTests \
    -only-testing:KototoroUITests/ProductFlowTests/testBatchMigrationReviewsTwoWorksAndMissingSourceRecoverySurvivesRestart \
    -only-testing:KototoroUITests/ExtensionPresentationTests test
```

共享规则测试覆盖跨生态 ID、大整数身份、去重、冗余扩展组合及未匹配来源。
Native 库测试覆盖来源元数据重开、解析器提供扩展身份、候选歧义、部分迁移失败与重试，
以及既有收藏分类、进度映射、原书签保留和目标较新进度合并。
UI 用例使用两个本地 CMS 来源，覆盖双作品搜索、核对、复制迁移、重启，
以及目标来源移除后的恢复提示和可读来源名称。该用例不验证真实第三方扩展的批量安装。

2026-10-16 验证结果（Apple Silicon、iOS 27 模拟器）：`core-domain` 159 项、iOS Native 84 项、
扩展展示回归 11 项及上述双作品端到端用例均通过。默认构建与包含现有真实扩展运行时的
`RecoveryRealApi` 构建均通过；真机与真实第三方扩展的批量安装仍需独立验收。

同日体验优化验证：新增 3 项批量选择范围测试，与 11 项扩展展示回归一并通过；增强端到端用例验证
空结果不能全选、跳过状态不被批量同名匹配覆盖、手动补选后双作品迁移，以及缺失来源页名称搜索与重启恢复。
默认构建与包含扩展运行时的构建均通过。
