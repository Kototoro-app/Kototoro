# Android / Windows 功能与 Compose 共享对照

更新日期：2026-10-14。以 `app`、`core-ui`、`desktop-app` 当前代码为依据；Android 是迁移基准，存在实现不等于本轮已逐项做真机验收。

## 判定方式

- **共享**：Android 和 Windows 实际调用同一份 `core-ui/commonMain` Compose。
- **部分共享**：已有共同组件，但页面仍包含独立 Windows 布局。
- **独立**：Windows 页面另有实现；共享业务规则不算共享 UI。
- **可用 / 部分 / 未接入**：描述功能范围，与 UI 共享情况分别记录。
- 平台适配允许保留：数据源、文件访问、窗口、Android 资源/触觉/TV 焦点、图片加载、Media3/libmpv/WebView2 等。迁移优先提取 Android 已有 Compose，平台适配层不复制布局。

## 当前实施项：P0 漫画阅读器基础目录

已迁移 `app/.../details/ui/pager/chapters/compose/ChapterItemCard.kt` 和 `ChaptersScreen.kt` 的 Compose 布局。Android 详情和阅读器继续调用原入口，内部改为共同组件；保留资源解析、触觉、TV 焦点、详情嵌套滚动和滚动条适配。Windows 阅读器移除独立列表，使用同一列表/网格、卡片和筛选轨道，接入既有分支/卷分组规则，补定位当前章、网格切换以及鼠标拖动。面板、标题、标签栏与搜索框也复用共同组件。

定位清除搜索并恢复当前章的分支，默认 `null` 分支不会被其他选择覆盖。当前章点击仅关闭目录，原阅读场景、页码和历史不变；其他章仍走原控制器加载。目录进度显示当前阅读分支内的序号/总章数。下载标记复用下载存储的章节身份判断，避免标题更新使已下载状态消失。

未命名且编号为 0/未知的章节在空查询时仍完整显示；未知编号不伪装成“第 0 章”。数字格式复用 parser-api 的 `formatSimple`，标题回退使用 Android 现有资源。标题、编号、小数编号与卷号搜索沿用共同规则。

已满足的门槛：两端调用共同组件；Android 编译通过；共同布局的列表/网格、定位、分组、重复 ID、卡片状态及输入行为有回归；真实 Windows 阅读器入口验证保持原加载、进度、返回和搜索快捷键语义。目标验证覆盖 520/1260 的完整阅读器和 340/960 的共同布局。

本项不代表“整个章节管理已完成”：Windows 详情入口、控制栏整体组装、多选、可折叠组、新章标记和额外来源标签仍待对齐；批量下载/删除/标记单独记录，未接入的能力不伪装成可用控件。下一项优先迁移详情目录，同时保留已有单章下载操作。

## 迁移原则

按可独立验证的功能逐项推进，优先 Android → `core-ui` → Windows 的真实复用。共享组件只处理布局、显示及输入；平台控制器继续负责数据和副作用。保留必要插槽而不增加第二套 Windows 布局或通用框架。每项完成后更新本表，注明测试和仍未对齐的范围。
