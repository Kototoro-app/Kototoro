# TV UI 实施计划

日期：2026-09-11。状态：阶段 1—4 已完成代码接入，阶段 5 的电视启动资源已接入；本文仍不代表功能已通过真实设备验证。

## 1. 目标与范围

采用同一应用、共享 Navigation3 和业务层、独立 TV 展示与遥控器交互的方案。
先完成真实电视上的操作闭环，再扩展页面，最后完善视觉和发布能力。

第一版目标：用户仅用遥控器启动应用、选择空间与内容、搜索、进入详情、阅读漫画或播放视频，
并正确返回原位置和焦点。

| 范围 | 第一版要求 |
| --- | --- |
| Android TV / Google TV | 自动采用 TV 界面，支持电视桌面启动 |
| 普通 Android 盒子 | 提供手动 TV 模式，兼容设备识别不准确的情况 |
| 手机、平板 | 保持现有默认布局和操作 |
| 手机手动开启 TV 模式 | 可用于预览，提供可操作的退出入口 |
| 漫画 | 单页、双页、长条模式的基本遥控操作 |
| 视频 | 播放暂停、快进退、选集、字幕和音轨选择 |
| 小说 | 第一版暂不承诺完整适配，明确展示支持范围 |
| 深层管理功能 | 可保留现有视觉，必经操作必须支持遥控器 |

不将全部高级功能的 TV 重设计作为首版门槛，但必经页面不能出现遥控器无法继续或退出的情况。

## 2. 当前代码基础与架构边界

以下路径相对于 `app/src/main/kotlin/org/skepsun/kototoro/`：

| 代码 | 当前作用与实施约束 |
| --- | --- |
| `main/ui/navigation3/MainTopLevelNavDisplay.kt` | 各 Tab 分别维护 entry 保存状态与 ViewModel 生命周期，继续复用 |
| `main/ui/compose/KototoroApp.kt` | 协调顶部、底部控件、Space、内容留白及转场，TV 外壳切换必须覆盖这些边界 |
| `main/ui/compose/MainShellScene.kt` | 保留共享导航与路由渲染，不能仅复制此文件建立 TV 导航世界 |
| `core/ui/widgets/KototoroBottomNav.kt` | 复用 `BottomNavState` 的目的地、选中项、可见性和徽标，独立实现 TV 视觉 |
| `core/util/FoldableUtils.kt` | 首阶段保留现有平板策略，不进行全面职责迁移 |
| `core/prefs/AppSettings.kt` | 增加展示模式偏好，保留 `TabletUiMode` 的既有语义 |
| `home/ui/HomeViewModel.kt` | 已组织续读、更新、推荐等数据，TV 首页优先复用 |
| `reader/ui/ReaderControlDelegate.kt` | 已有方向键翻页、滚动和中心键显隐，先审计分发再扩展 |

保留 `MainNavState`、`MainNavigator`、Navigation3 key、每 Tab 返回栈和 Space 导航状态。
Repository、内容源、实体体系、阅读器和播放器内核继续共享。

展示结构：

```text
设备配置与用户设置 → 展示模式解析 → 标准外壳 / TV 外壳
                                      │
Space 与 Navigation3 状态 → 共享路由分发
                                      │
                    复用页面 / 适配列表 / TV Home 与 Details
                                      │
                            共享 ViewModel 与业务层
```

外壳切换不得意外重建 `NavDisplay`、Space 状态或导航 entry 生命周期。
TV 默认复用现有 ViewModel；确有独立展示状态需求时，可以增加薄的状态持有者，不能复制业务流程。

## 3. 展示模式

首阶段新增：

```kotlin
enum class UiPresentationMode {
    AUTO,
    STANDARD,
    TV,
}
```

解析顺序：

1. 用户指定 `TV`：使用 TV 展示。
2. 用户指定 `STANDARD`：使用既有手机／平板策略。
3. `AUTO`：检查系统电视模式与设备特征，其他设备沿用标准展示。

保留 `TabletUiMode`，不立即迁移为 `AUTO / PHONE / TABLET / TV`。
这样 TV 实现不会同时改变已有平板偏好的语义与默认行为。

实现要求：

- 分离平台特征读取与纯粹的模式决策，便于测试。
- 主界面、设置、阅读器和播放器采用一致的解析规则。
- 各 Compose 根节点提供当前展示配置，不能假设主 Activity 的 CompositionLocal 跨 Activity 生效。
- 窗口空间继续参与布局计算，不能将 TV 身份简单等同于可用宽度。
- 连接鼠标、键盘或遥控器不会触发整个界面突然切换。
- 手动 TV 模式必须提供清晰的恢复标准界面入口。

暂不建立完整的 `InputProfile`、`WindowProfile` 或动态输入设备状态系统。

## 4. TV 外壳与导航

独立实现 TV 主导航，复用导航目的地与选择回调，不把现有底栏的全部视觉偏好带入 TV。

第一阶段采用固定宽度导航，优先验证焦点路径。规则如下：

- 上下键移动导航焦点；确认键切换页面，焦点经过项目不自动切页。
- 当前页面和当前焦点分别呈现，选中状态不能代替焦点反馈。
- 内容区域向左到达边界后进入导航。
- 导航向右返回内容区最近的有效焦点。
- 首次进入页面使用明确的默认焦点。
- Space 切换后恢复该空间的页面与焦点。
- 搜索、设置和 Space 切换具有明确的遥控器入口。

TV 导航保持固定宽度，不随焦点自动展开或收起，避免内容重排及覆盖层点击冲突。

当前实现为固定 84dp 图标导航栏，内容避让直接采用导航栏实际测量宽度。

2026-09-13 操作稳定性优化：导航增加常驻单行标签；重新进入导航时恢复上次焦点，
失效则回退到当前可见选中项或首个可见项。导航不再随页面选择主动请求焦点。
导航按钮与共享列表卡片复用可点击控件的焦点节点；卡片焦点变化和首页推荐刷新不再重复请求默认焦点。
焦点回退策略由单元测试覆盖；跨页面返回、连续方向键和确认键行为仍需设备验收。

设置操作行、单选／多选项、弹窗按钮与搜索筛选复用实际点击／切换节点的焦点，
避免额外焦点截走确认键；多选上限禁用项沿用原控件的禁用规则。
TV 搜索筛选按钮至少 48dp 高并使用较大标签，开关整行只保留一个切换入口。

章节列表／网格的焦点请求器绑定到实际章节点击节点，详情封面及操作按钮不再增加重复焦点。
播放器图标与文字按钮复用内置焦点，TV 文字按钮至少 48dp 高；进度条按键监听放在焦点节点之前，
左右键由进度条处理，上下键继续交给焦点导航。以上交互仍需设备验证。

## 5. 焦点系统与恢复

先建立少量 TV 卡片、按钮、导航项和恢复辅助逻辑，统一边框、背景、缩放和动画。
为放大效果预留空间，避免被父容器裁切。

优先使用 Compose 自带焦点分组和恢复机制，仅补充跨路由、Paging 和 Space 所需状态。

| 焦点记录语义 | 用途 |
| --- | --- |
| Space 标识 | 隔离空间 |
| 导航 entry 身份 | 隔离同一路由的不同实例 |
| 内容区域标识 | 区分首页横排或页面面板 |
| 稳定项目标识 | 确认实际内容身份 |
| 索引提示 | 辅助滚动定位，不作为最终身份依据 |

不持久化 `FocusRequester`，不使用无法明确保存的任意对象作为恢复标识。

恢复顺序：

1. 确认目标页面已成为当前活动页面。
2. 恢复列表滚动状态。
3. 检查加载状态与目标是否存在。
4. 必要时滚动到目标附近。
5. 等待目标进入布局并绑定焦点请求器。
6. 请求焦点；目标失效时执行回退。

回退顺序：原项目 → 原位置附近有效项目 → 区域默认操作 → 页面默认操作。

Paging 恢复必须有结束条件，不无限等待某个 ID，也不为恢复焦点加载整个内容库。
导航转场中的非活动页面不得抢占焦点。弹窗关闭、Tab 切换、播放器返回均需单独验证。

## 6. 现有列表适配

收藏、历史、更新、探索和搜索优先复用当前 screen 与数据状态，调整：

- 卡片尺寸、文字层级、信息密度、间距及焦点放大留白。
- 分类、筛选、排序和更多菜单入口。
- 网格边界与导航区域之间的焦点路径。
- 滚动跟随焦点和长按操作的显式菜单入口。
- 空状态、加载状态和错误重试。

每个页面按完整操作验收。例如收藏页：

```text
切换分类 → 打开作品 → 返回 → 排序 → 打开筛选 → 修改条件 → 关闭面板 → 继续浏览
```

只为当前组合中的项目绑定焦点请求器，不建立所有内容项目的全局焦点对象表。

## 7. TV Home 与 Details

### Home

复用已有续读／续播、最近更新、推荐和收藏入口等可靠数据。
不为 TV 首页额外引入新的推荐请求或后台聚合任务。

先实现标题和横向内容行，再增加 Hero。自动轮播不得抢焦点，不能在用户操作时改变目标内容。

### Details

独立组织背景图、封面、标题、关键元信息、继续／开始操作、收藏、源切换、更多操作、章节与关联内容。
共享现有详情回调，避免复制收藏、进度和章节选择逻辑。

首次焦点通常落在继续／开始按钮；从阅读或播放返回时恢复之前的位置。
长章节列表采用现有懒加载或分页，不一次性组合全部章节。

## 8. 漫画阅读器

先审计 `ReaderControlDelegate`、Activity 按键回调和 Compose 焦点的关系。
事件优先级为：弹窗／菜单 → 已显示控件 → 阅读内容。

| 状态 | 操作 |
| --- | --- |
| 内容浏览 | 左右翻页，上下按阅读模式滚动 |
| 长条阅读 | 上下按视口步进，长按连续滚动 |
| 确认键 | 显示控件，并将焦点交给默认操作 |
| 控件显示 | 方向键移动焦点，不同时翻页 |
| Back | 先关闭菜单或控件，再退出阅读 |

覆盖从右向左阅读、现有反转设置、按键重复、双页翻页粒度、章节边界和页码／章节选择。
验证返回详情后的进度与焦点。

缩放、OCR、裁剪等高级操作后续单独适配，不阻塞基本阅读路径。

## 9. 视频播放器

复用播放内核，增加遥控器控制状态与必要的 TV 控件布局。

| 场景 | 行为 |
| --- | --- |
| 控件隐藏时确认 | 显示控件并聚焦主要操作 |
| 播放／暂停媒体键 | 切换播放状态 |
| 进度条获得焦点 | 左右调整进度 |
| 字幕／音轨菜单 | 方向键浏览，确认选择 |
| Back | 先关闭菜单，再关闭控件，最后退出 |
| 连续操作 | 控件不自动隐藏 |

实现前明确 seek 的提交方式与长按规则，避免按键重复触发昂贵操作。
首版覆盖暂停、快进退、上下集、选集、字幕、音轨、失败重试、播放结束和返回详情。
Media3 内核可复用不等于自定义播放器控件已具备遥控器支持。

## 10. 必经配置与系统流程

开发早期审计首次启动、源选择／启用、搜索输入、设置、TV 模式退出、必要权限、网络重试与必要登录。

系统文件选择器、第三方登录和 WebView 挑战需要真机验证，不能仅凭应用内测试判断可用。
高级配置若首版不支持，应明确边界。使用预配置数据测试不能代表首次安装流程已经通过。

## 11. 组件、视觉与启动入口

用一个导航项、一张卡片和一个对话框，对比现有组件封装与 TV 组件的：

- 按键完整性和焦点稳定性。
- 主题一致性。
- 依赖与包体影响。
- 实现和维护成本。

根据实际缺口决定是否引入 `androidx.tv`，不预先承诺全部自建，也不全面替换现有组件。

视觉优先保证远距离可读、焦点明显、控件间距、长标题截断与滚动稳定。
玻璃、模糊和共享元素动画后置，并在低性能电视上验证。
TV 不直接继承手机全部视觉偏好组合。

测试版本尽早加入电视启动入口，检查 `LEANBACK_LAUNCHER`、banner、
`android.software.leanback` 与触摸屏非必需声明的适用配置。
兼容手机的 APK 不能将 leanback 声明为必需。
电视桌面可启动与正式商店发布分开验收，不能把启动入口拖到发布阶段才处理。

## 13. 验证方案

按改动范围执行：

- 模式解析、焦点回退和按键路由：针对性单元测试。
- Kotlin 改动：`./gradlew :app:compileDebugKotlin`。
- JVM 测试：`./gradlew :app:testDebugUnitTest --no-daemon`，开发中优先限定相关测试。
- 焦点移动、弹窗与返回：Compose／设备测试，必要时运行 `:app:connectedDebugAndroidTest`。
- 候选版本：构建 APK、实际安装和遥控器验收。

重点场景：

1. 长列表打开详情后返回原项目。
2. 原项目删除后有合理焦点回退。
3. Tab 和 Space 分别恢复状态。
4. Paging 加载、刷新和失败时焦点稳定。
5. 弹窗关闭后回到触发按钮。
6. 连续方向键不越界、不卡死。
7. 阅读／播放控件与内容不争抢按键。
8. 应用重建后恢复合理页面，不向失效目标请求焦点。
9. 手机、平板的导航、详情和阅读行为正常。

至少覆盖一台真实 TV／盒子、一个 TV 模拟器，以及手机和平板回归环境。
Debug 默认仅构建 `arm64-v8a`，其他架构模拟器需先解决 ABI 匹配。
设备检查优先采用可用的 Android CLI／ADB，截图和 APK 不纳入版本控制。

## 14. 目录与改动控制

按现有功能模块组织，仅创建当前阶段需要的文件：

```text
core/ui/adaptive/          展示模式解析与提供
core/ui/components/tv/     少量共享 TV 组件
main/ui/compose/tv/        TV 外壳与导航
home/ui/compose/tv/        TV 首页
details/ui/compose/tv/     TV 详情
reader/ui/                现有控制分发及必要扩展
video/ui/                 遥控器控制与 TV 控件
```

不建立平行业务模块，不预建空框架，不将标准底栏或 `FoldableUtils` 的全面重构设为前置任务。
以共享业务遵循 DRY，以分离展示与控制职责落实单一职责，以逐阶段交付控制复杂度和回归范围。

首个交付里程碑：从电视桌面启动，遥控器选择内容、进入详情、按 Back 返回并恢复原焦点，
同时手机和平板的现有布局不受影响。
