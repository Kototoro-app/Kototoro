# 贡献准则 (Contributing)

本项目高度重视聚焦、改动范围清晰且能为用户带来明确价值的 Pull Request。

---

## 提交 PR 前的自检清单

1. 确认该问题是可复现的，或者所提出的功能需求是具体明确的。
2. 保持改动范围聚焦，不要在一个 PR 中混杂无关的重构或格式化。
3. 在本地完整验证受影响的功能流程与构建测试。
4. 当用户可见行为或设置步骤发生改变时，请同步更新 `docs/` 下的对应中英文文档。

---

## 对 Pull Request 的期望

- 清晰解释改动了什么，以及为什么要改（Motivation & Context）。
- 说明对最终用户的直观影响。
- 附带本地验证所使用的命令或截图。
- 如有已知限制或未完成部分，请在说明中诚实列出。

---

## 提交 Issue 建议

一份有价值的 Issue 报告通常应包含：

- 应用的具体版本号（如正式版版本或 Nightly 日期）。
- 设备型号与 Android / 操作系统版本。
- 明确、可一步步复现的步骤。
- 相关的系统日志（Logcat）或屏幕录像。
- 说明该问题仅发生在特定源，还是全局功能都会发生。

详细指引请参考 [问题提报指南](./issue-submission-guide.md)。

---

## 文档规范

- 项目根目录的 `README.md` 保持简练，突出产品核心亮点。
- `docs/` 用于存放针对具体任务的用户指南、故障排查与技术参考。
- 新功能提交时通常应补充或更新对应的操作手册。
