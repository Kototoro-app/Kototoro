# 改进 Space FAB 与主导航栏布局

## Goal

在不改变当前 Space 切换入口和跨页面位置语义的前提下，打磨 Space FAB 与主导航栏的视觉层级、空间适配和沉浸式页面避让体验。

用户应始终能在熟悉的右下区域找到 Space 切换入口；主界面启用 FAB 后，不应因为布局竞争而被迫减少用户配置的主导航按钮数量。

## Confirmed Facts

- 主界面通过 `KototoroBottomNav` 的 `adjacentAction` 将 Space FAB 放在底部导航右侧。
- 作品列表和详情页使用右下角浮动入口；详情页已有底部面板遮挡量计算，并在底部面板展开时隐藏 FAB。
- 阅读器和播放器使用沉浸式 FAB；播放器会根据底部 `controlBar` 高度把 FAB 上移，阅读器当前需要继续避让底部工具栏及缩放/计时控件。
- 主导航项数量由 `NavItem.kt` 中的 `MAX_MAIN_NAV_ITEM_COUNT = 4` 限制。
- 项目已有 `GlassSurface`、`GlassBottomBarContainer` 和按 `BottomBar`/`TopBar` 角色解析的 Haze 玻璃样式，FAB 可复用现有玻璃基础设施。
- Space 切换行为、Space 面板和 FAB 的跨页面入口位置不在本任务中重做；本任务只改 UI 布局、样式和避让策略。

## Requirements

- R1. 主界面保留 Space FAB 位于底部导航右侧的布局关系；在 FAB 显示时，主导航仍允许保持当前产品上限的导航项数量，不因 FAB 默认降为 4 项。
- R2. 主导航栏与 FAB 根据可用宽度自适应，优先调整外部留白、项目间距和标签显示；触摸目标不得缩小到 Material 推荐的 48dp 以下。
- R3. FAB 与导航栏使用同一套玻璃视觉语言，但通过形状、强调色、边框/阴影层级区分 FAB 与底部导航，确保 FAB 是 Space 上下文入口而不是导航项。
- R4. 作品列表和详情页继续使用右下浮动入口；FAB 不得遮挡底部操作面板、详情底部面板或主要内容交互区域，面板展开时应隐藏或避让。
- R5. 阅读器和播放器继续使用右下浮动入口；FAB 只在沉浸式控制层可见时显示，并动态避让底部控制栏及页面已有的右下角辅助控件。
- R6. 自适应布局在手机窄屏、横屏/平板导航栏模式、系统手势/导航栏 inset 和导航栏显示/隐藏动画下保持稳定，不出现裁剪、重叠或跳动。
- R7. 保持现有 Space 切换面板、切换流程、动效语义和无障碍 content description；新增或调整的 UI 状态应有可验证的布局/组件测试或明确的手工验收步骤。

## Acceptance Criteria

- [ ] 主界面在 FAB 显示时可展示产品允许的主导航项数量，窄屏下通过布局压缩或标签降级解决空间不足，而不是静默丢弃导航项。
- [ ] 导航栏项目和 FAB 的最小可点击区域不低于 48dp，导航栏与 FAB 之间有稳定间距。
- [ ] FAB 使用 Haze/GlassSurface 体系并与导航栏有明确的视觉区分，在明暗主题下均保持图标对比度。
- [ ] 作品列表、详情页、阅读器、播放器的 FAB 均位于右下动作区，且对底部控制层和辅助控件无重叠。
- [ ] FAB 随控制层显示/隐藏及导航栏位置变化平滑过渡，不产生错误锚点或跨 Space 残留。
- [ ] Debug 编译、相关 JVM 单测和 lint 通过；若 AndroidTest 仍被仓库既有旧 API 测试阻塞，必须记录具体阻塞文件和与本任务的关系。

## Out of Scope

- 不把 Space FAB 改成顶栏按钮。
- 不把 Space 面板改成顶栏锚定 Popup 或重做 Space 列表信息架构。
- 不重新设计主导航项的业务排序、权限和配置入口。
- 不修改 Space 切换的数据模型、切换事务或跨 Space 导航状态。

## Resolved Decisions

- 主导航产品上限恢复为 5 项，并让 FAB 参与可用宽度预算。
- 窄屏优先通过隐藏标签、收紧间距和外部留白来适配；不缩小导航项或 FAB 的最小触摸目标。
- Compose 页面使用现有 Haze/GlassSurface 管线；阅读器和播放器保留传统 View 结构，使用同一套颜色、边框、圆角和层级 token 做视觉 fallback，不为 FAB 改造整套页面。
