# 处理 GitHub Issues 404、405、407、408、409、411

## Goal

按用户确认的优先顺序修复或调整 #404、#405、#407、#408、#409、#411，并为每个问题补充可验证的回归保护。#403 信息不足而忽略，#406 属于用户对 Space FAB 语义的误解而忽略，#410 已由 PR 合并解决。

## Confirmed Scope

- #404：图标背景开启后，浏览页顶部轮播卡片底部的纯色渐变与动态图片背景突兀；需要调整为更适合图片背景的半透明渐变或等价视觉方案。
- #405：不是缺陷，而是 Modern/iOS 风格配色能力调整；允许自定义配色，并将配色说明改为明确的 iOS 风格默认预设文案；缺失的预设需要补齐。
- #407：关闭 Space 时，主界面顶栏右侧内容类型过滤按钮需要支持长按原地展开、拖拽切换视频/漫画/小说；当前缺少 Backdrop、小说按钮不显示，原始按钮不应额外包容器。
- #408：详情页初次打开时可能不显示 `reading source`，下拉刷新后出现；重点检查详情缓存的保存与读取时序。
- #409：更新到 1.6.3 后，原本拥有多个 projection 的收藏作品只显示部分 projection；需要保证完整投影集合可见，并保护迁移后的数据。
- #411：Android 16、Kototoro 1.6.3 在绘制阶段发生 `OutOfMemoryError`；已有完整崩溃日志，需要定位应用侧内存压力来源并修复或增加可靠防护。

1. 严格按子任务顺序交付；每个子任务完成后运行对应测试并检查工作区，再进入下一个。
2. 保持非目标风格、非目标页面和已有 Space 数据行为不回归。
3. 优先复用已有 Backdrop、主题、详情数据流和实体投影迁移基础设施，不引入平行实现。
4. #408/#409 不得通过简单刷新或 UI 兜底掩盖数据层不一致；必须验证初次加载和已有数据库数据。
5. #411 在根因未被证据确认前不得盲目增加全局缓存清理或静默吞掉 OOM；必须记录定位证据和保护边界。
